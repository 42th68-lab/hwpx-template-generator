# 한폼 — HWPX 양식 생성

자연어 요구사항이나 PDF/HWPX 안내문에서 문서 조건을 읽고, 설정을 확인·수정한 뒤 HWPX 양식을 만드는 서비스입니다.

**[한폼 접속하기](https://hanform.vercel.app/)** — 회원가입이나 로그인 없이 이용합니다. Production에는 Gemini를 연결했으며 현재 `gemini-3.5-flash-lite`로 조건을 분석합니다. 키가 없는 로컬·Preview 환경은 기본 분석으로 동작합니다.

## 실행 방법

Node.js **24.x**에서 프로젝트 폴더를 열고 실행합니다.

```powershell
npm ci
npm start
```

브라우저에서 `http://127.0.0.1:4173`을 엽니다. 종료는 터미널의 Ctrl+C입니다. 선택 환경변수 `PORT`로 포트를 바꿀 수 있습니다. HTML 파일을 직접 열면 서버 기능을 사용할 수 없습니다.

1. 요구사항을 입력하거나 안내 PDF/HWPX를 첨부하고 **문서 조건 분석하기**를 누릅니다.
2. 용지·여백·글꼴·본문 크기·줄 간격·필수 항목과 근거를 확인합니다. 누락이나 충돌은 직접 수정·확인해야 합니다.
3. 필요한 경우 표지, 목차, 표로 작성할 항목을 선택하고 **설정 확정하기**를 누릅니다.
4. 제목을 입력하고 **HWPX 양식 만들기**를 누른 뒤 파일을 내려받습니다.
5. 계속 사용할 양식은 **내 양식에 저장**합니다. 설정을 수정하면 다시 확정·생성해야 합니다.

LibreOffice는 서비스 실행·배포에 필요하지 않습니다. 한글에서의 최종 열기·배치·쪽수 점검은 사용자가 진행합니다.

## 현재 지원 범위

| 기능 | 동작 |
| --- | --- |
| 입력 | 자연어 500자, PDF/HWPX 최대 3개. 파일당·전체 합계 3,500,000바이트 이하. |
| 본문 추출 | 문자 PDF 30쪽 이하, HWPX 본문·표 셀. 본문 앞 10만 자까지 분석하며 생략 시 경고. 원본 파일은 서버에 보관하지 않음. |
| 조건 분석 | 용지 A3/A4/A5/B4/B5/Letter/Legal, 방향, mm/cm 여백, 글꼴, pt 크기, %/pt/배 줄 간격, 명시적인 필수 항목. 기본 분석은 모호한 조건을 추측하지 않음. |
| 확인·수정 | 근거·누락·충돌·잘못된 값 표시. 미확인 충돌이나 잘못된 설정은 생성 차단. JSON 내려받기 지원. |
| HWPX 서식 | 용지·방향·네 방향 여백·글꼴·본문 크기·줄 간격 적용. 제목 20pt, 항목 제목 14pt. 글꼴은 파일에 포함되지 않으므로 한글 실행 컴퓨터에 설치되어 있어야 함. |
| 추가 구성 | 선택형 표지(작성자·소속·작성일 빈칸), 별도 목차 페이지, 선택한 필수 항목의 기본 3행 2열 작성 표. 목차는 항목 목록이며 자동 쪽번호 필드는 아님. |
| 미리보기 | 용지·여백·글꼴·크기·줄 간격·표·추가 페이지 구성을 브라우저에 반영. 한글과 동일한 줄바꿈·쪽 나눔을 보장하지 않음. |
| 파일 검사 | ZIP/CRC, mimetype, 필수 XML과 연결, 스타일 참조·개수, 문단 ID, 낡은 레이아웃 캐시 검사. 손상·가짜 형식 입력 거부. |
| 내 양식 | 이름·입력 조건·설정·HWPX를 브라우저 IndexedDB에 저장. 검색·불러오기·복사·삭제·최근 수정 이력 20개 복원. |
| 온라인 보관 | Supabase 비공개 테이블·Storage에 명시적으로 저장. 공개 체크 해제 시 관리 정보가 있는 사람만 조회·다운로드. 온라인 수정 이력 최근 10개. |
| 공개 양식 | 명시적 공개 선택, 익명/이름 표시, 입력 조건 공개 여부 별도 선택. 제목·공개 이름·필수 항목 검색, 페이지 이동, 다운로드·내 양식으로 복사. 원본 첨부·추출 본문은 공개하지 않음. |
| 백업 | JSON 백업 내보내기·가져오기. 이름·조건·설정·이력·온라인 관리 정보 포함. HWPX 바이트는 백업하지 않고 다시 생성. |
| 계정 | 회원가입·로그인·메일 인증 없음. 브라우저 보관과 별도 관리 정보로 소유권 구분. |

본문 크기는 1~100pt, 여백은 0~150mm이며 실제 본문 공간도 검사합니다. 줄 간격은 최대 500%/200pt/5배, 필수 항목은 50개·각 100자입니다. HWPX 압축 해제 크기는 항목당 20MB·전체 50MB, ZIP 항목 1,000개, 본문 구역 100개, 핵심 XML 각각 2MB 이하로 제한합니다.

아직 지원하지 않는 범위는 바이너리 `.hwp`, 스캔 PDF OCR, 암호 PDF, 원본 디자인의 정밀 복제, 임의의 그림·수식 생성, 자동 쪽번호 목차, 한글과 동일한 페이지 렌더링입니다. 구조 검사 통과와 한글 최종 화면 확인은 별개입니다.

## 보관·공개·다른 컴퓨터에서 사용

**내 양식에 저장**은 이 브라우저에 저장합니다. 파일까지 생성한 뒤 저장하면 HWPX도 함께 보관합니다. 설정만 저장했거나 백업에서 가져온 경우 내려받을 때 다시 생성합니다. 브라우저 데이터 삭제로 보관본이 지워질 수 있으므로 백업을 내려받으세요.

저장 카드의 **온라인 보관·공개 설정**에서 설정 저장을 누르면 온라인에도 보관합니다. 기본값은 비공개입니다. 공개 체크를 선택한 경우에만 다른 방문자가 검색·조회·다운로드할 수 있습니다. 공개할 이름과 입력 조건 공개는 별도로 선택합니다. 내 양식을 수정한 후 온라인에도 반영하려면 이 창에서 다시 저장합니다.

다른 컴퓨터에서는 JSON 백업을 가져오고 **온라인 최신본 불러오기**를 눌러 최신 설정·온라인 이력을 가져올 수 있습니다. 백업에는 온라인 양식을 수정·삭제할 수 있는 관리 정보가 들어 있으므로 본인이 보관하세요. 다른 사람에게는 공개 양식의 **공유 링크 복사**로 얻은 링크를 보내면 됩니다. 관리 정보를 잃으면 계정 복구 방식으로 소유권을 되찾을 수 없습니다.

공개 양식을 **내 양식으로 복사**하면 독립적인 보관본이 생깁니다. 수정해도 공개 원본과 원본의 관리 권한은 바뀌지 않습니다. 중복 백업을 가져오면 별도 로컬 보관본이 추가됩니다.

## Supabase 구조와 권한

승인된 무료 프로젝트 `hanform` (`oealbssaoxeizrqosvzp`, 서울)과 Vercel 프로젝트 `hanform`을 사용합니다. 기존 계정 기반 `document_forms`·`hanform-private`는 이력으로 유지하고 현재 화면에서는 사용하지 않습니다. 신규 회원가입은 비활성화 상태입니다.

- `public.guest_templates`: 이름·조건·설정·공개 여부·수정 이력·파일 경로·버전과 관리 토큰의 SHA-256 해시. RLS를 강제하고 anon/authenticated의 직접 접근을 차단합니다. 사용자용 직접 접근 정책을 두지 않은 것이 의도한 설정입니다. 보안 검사에는 이 때문에 INFO 안내 1개가 표시됩니다. ([RLS 정책 안내](https://supabase.com/docs/guides/database/database-linter?lint=0008_rls_enabled_no_policy))
- `hanform-shared`: 비공개 HWPX 버킷, 파일 최대 2MB. 브라우저의 직접 열람·수정·목록 조회 및 영구 공개 URL을 허용하지 않습니다.
- `guest-library` Edge Function: 연결 키를 검사하고, 비공개 조회·수정·삭제에는 256비트 무작위 관리 토큰을 추가 검증합니다. 공개 응답에서 관리 토큰·해시·비공개 입력 조건·이력을 제외합니다. 버전 검사로 오래된 보관본의 덮어쓰기를 차단합니다.
- Edge Function의 `verify_jwt=false`는 새 publishable 키를 사용하기 위한 설정이며 함수 내부의 연결 키·소유권 검사를 사용합니다. 익명 Auth 계정을 만들지 않습니다.
- 서버 내장 비밀 키는 Supabase가 함수에 제공하는 환경변수로만 읽습니다. 브라우저·Git·Vercel 환경변수에 관리자 키를 넣지 않습니다. 온라인 신규 보관은 전체 5,000개까지 제한합니다.

변경 내역:

- `supabase/migrations/20261030073304_guest_template_library.sql`
- `supabase/migrations/20261030080015_private_guest_backups.sql`
- `supabase/functions/guest-library/index.ts`, `handler.mjs`
- `supabase/config.toml`: 재배포 시에도 함수의 자체 인증 설정과 진입점을 유지. ([함수 설정 문서](https://supabase.com/docs/guides/functions/function-configuration))

마이그레이션을 적용한 뒤 같은 이름의 Edge Function을 위 설정으로 배포합니다. 원본 PDF/HWPX를 온라인에 업로드하는 API는 없으며, 검증한 설정으로 서버가 만든 HWPX만 저장합니다.

## 환경변수

`.env.example`을 참고합니다. `.env`는 Git·배포 소스에서 제외합니다. `/api/config`는 설정 여부와 제한만 반환합니다.

| 이름 | 용도 |
| --- | --- |
| `SUPABASE_URL` | 온라인 보관·공개 저장소 연결 주소. 로컬 및 Vercel 서버에서 사용. |
| `SUPABASE_PUBLISHABLE_KEY` | 서버가 Edge Function에 연결할 공개 연결 키. 현재 배포에 설정됨. 관리자 권한 키가 아님. |
| `GEMINI_API_KEY` | 선택. Production에 사용자가 직접 Secret으로 설정함. 없으면 기본 분석 사용. 키 값은 조회·출력·Git 저장하지 않음. |
| `GEMINI_MODEL` | 선택. 현재 Production 및 기본 모델은 `gemini-3.5-flash-lite`. 실제 호출 검증 완료. |
| `PORT` | 로컬 포트, 기본 4173. Vercel에는 불필요. |

Gemini를 설정하면 요구사항과 첨부에서 추출한 본문이 Gemini에 전송됩니다. 키·모델·연결 오류는 키를 노출하지 않고 경고 후 기본 분석으로 전환합니다. Supabase 연결이 없어도 분석·생성·로컬 보관·백업은 이용할 수 있으며 온라인 기능만 사용할 수 없습니다.

Gemini 3·4 계열에는 빠른 조건 추출을 위해 `thinkingLevel=low`를 요청합니다. 호출 전체 제한은 45초입니다. 제공자가 요청 옵션을 `INVALID_ARGUMENT`로 거부하면 같은 제한 시간 안에서 추론 옵션을 제외하고, 필요한 경우 JSON 모드로 재시도합니다. 결과의 값·출처·정확한 원문 인용 검증은 동일하게 유지합니다. 키·권한·할당량·결제 문제는 이 재시도 대상이 아닙니다. 오류 로그에는 정해진 진단 코드만 남기며 키나 제공자의 원문 오류를 기록하지 않습니다.

## Vercel 배포

서비스 주소는 **https://hanform.vercel.app/** 입니다. 팀은 `42th68-3089's projects`, 프로젝트는 `hanform`, Node.js 24.x, Fluid Compute, 함수 실행 60초입니다.

1. `npm ci`, `npm test`, `npm run test:real`, `npm run build`를 실행합니다.
2. 승인된 프로젝트에 연결하고 위 Supabase 변수 두 개를 필요한 배포 환경에 설정합니다.
3. 빌드 `npm run build`, 출력 `dist`, 설치 `npm ci` 및 `vercel.json`을 사용합니다.
4. Preview를 배포해 팀 로그인으로 확인한 뒤 Production으로 배포합니다. Preview에는 기존 배포 보호를 유지합니다.
5. 실제 주소에서 아래 배포 검사와 브라우저 검사를 진행합니다.

`npm run build`는 공개 화면 파일 **8개**만 `dist/`로 복사합니다. `scripts/deployment-files.mjs`의 배포 소스 **20개** 목록에는 원본 학교 자료·일지·키·테스트 결과를 넣지 않습니다. 정적 폴더에는 서버 코드·템플릿도 넣지 않습니다. `api/index.mjs`는 로컬과 같은 처리기를 사용합니다.

2026-10-27 확인한 Vercel 공식 제한은 함수 요청·응답 각각 **4.5MB**, Fluid Hobby 실행 최대 **300초**입니다. 이 앱은 업로드 3.5MB, 요청·JSON 응답 4,000,000바이트, HWPX 2,000,000바이트, 실행 60초로 제한합니다. base64 응답의 크기도 검사합니다. ([함수 제한](https://vercel.com/docs/functions/limitations), [실행 시간](https://vercel.com/docs/functions/configuring-functions/duration))

생성 응답에 파일 바이트를 반환하므로 다음 요청에서 이전 서버 인스턴스의 메모리나 임시 파일을 찾지 않습니다. 온라인 보관본은 비공개 Storage에서 권한 확인 후 내려받습니다. 서버 재시작에 의존하지 않습니다.

## 검사 방법과 완료 범위

```powershell
npm test
npm run test:real
node scripts/verify-deployed.mjs https://hanform.vercel.app/
node scripts/verify-library.mjs https://hanform.vercel.app/
```

실제 자료 검사는 로컬 `etc/`의 계획서 PDF/HWPX가 필요합니다. 없으면 `test:real`은 실패하고 일반 테스트의 해당 자료 항목은 건너뜁니다. 배포 검사 스크립트는 자료를 지정한 서버에 전송하므로 승인된 주소에만 실행합니다. 공개 저장소 검사는 합성 시험 양식을 만들고 본인 관리 정보로 정리합니다.

2026-10-30에는 자동 검사 **36개**, 실제 PDF/HWPX 전체 흐름, Production 문서 API 검사 **17개**, 온라인 보관·공개·서로 다른 관리 정보·비로그인 권한 검사 **34개**가 통과했습니다. 브라우저에서도 보관·수정 이력 복원·백업 이동·비공개 온라인 저장·다운로드·복사 후 원본 유지를 확인했습니다. 상세 결과와 소스 해시는 `deployment/completion-verification.json`에 기록합니다. 실제 Gemini 호출과 한글 최종 화면 점검은 완료로 표시하지 않습니다. 이번 확장 작업에서는 보호된 Preview의 새 접근 링크 발급과 불러온 양식의 실제 공개 동작이 자동 승인 검토에서 거부되어, 보호와 비공개 상태를 유지했습니다. 공개 기능은 별도 합성 시험 데이터로 검사했습니다.

2026-10-31에는 사용자가 Production에 저장한 Gemini 설정을 적용했습니다. `gemini-3.8-flash`의 시간초과·503 응답과 Flash-Lite 요청 옵션의 호환 문제를 확인해 모델·호출 처리를 조정했습니다. 자동 검사 **41개**, 실제 Gemini 전체 흐름 검사 **23개**가 통과했습니다. 자연어의 ‘열한 포인트 → 11pt’, 개인정보 없는 시험 PDF/HWPX 단독 첨부, 수정 설정의 HWPX 생성·구조 검사를 확인했습니다. 최신 배포·검사 기록은 `deployment/gemini-verification.json`입니다.

실제 Gemini 반복 검사는 승인된 배포 주소와 전송해도 되는 시험 파일을 명시해 실행합니다. 이 명령은 외부 서비스를 호출하므로 계정 사용량을 소비합니다.

```powershell
node scripts/verify-gemini.mjs https://hanform.vercel.app/ 시험안내.pdf 시험안내.hwpx
```

계획서 1~8차시의 입력·추출·설정 분석·미리보기·생성·배포·저장·검색·복사 흐름을 구현했습니다. 6~8차시의 계정 기반 계획은 사용자 요청에 따라 회원가입 없는 관리 정보 방식으로 바꿨습니다. 남은 수동 작업은 사용자의 한글 화면 점검입니다.

HWPX는 `hwpx-unified` 지침에 따라 검증된 기본 템플릿에서 수정하며 결과의 ZIP/XML 구조를 검사합니다. 독립 검증은 해당 스킬의 `scripts/validate_hwpx.py 파일.hwpx --changed-section Contents/section0.xml`로 반복할 수 있습니다. 시험 결과는 `tmp/`에 두고 Git과 배포에서 제외합니다.
